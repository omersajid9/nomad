01

The problem

Agentic kernel generation is active, but three gaps keep it from being a compiler.

why this matters
Gap 01

Single-vendor agents

The compiler-agent CAKE is NVIDIA-only. TritorX targets one ASIC. AWS's NKI agent needs a Trainium device in the loop. None retargets from a declarative hardware description.

Gap 02

Kernel-level, not graph-level

Fusion, data layout and rewrite synthesis move end-to-end performance. These decisions usually sit outside the agent's action space.

Gap 03

Correctness is empirical

Kernels are admitted by allclose or OpInfo tests. Audits find test-passing kernels that are still broken. Formal checkers are offline and NVIDIA-specific.

The concrete example: QKV

Why this block

It has a graph, a plan, a PKIR document, a lowering, a PTX artifact, a differential test and a timing result.

It also has a real semantic failure mode. Drop pad: zero and the last K-tile reads out of bounds. G1 still accepts it. G4 is the gate that catches it.

06

Blockers

The honest list. This is what a good midterm says out loud.

risk register

The full block is not expressible in PKIR v0.1

critical

RMSNorm, layout, SDPA and merge need reductions, exp/rsqrt, running softmax state, layout steps and masks. G1 rejects all four groups with S-UNSUPPORTED.

No GPU validation yet

critical

G4 and G5 are implemented but have not run on the RTX 3070/A40. On the Mac, G4 returns D-UNAVAILABLE. The GPU test is ready.

G2 is not symbolic equivalence

critical

G2 checks slot edges. It does not prove numeric equivalence. G4 samples the shape table. The proposal's soundness claim is not yet met.

NKI / Trainium is a stub

critical

There is no trn2.yaml and no NKI lowering. Portability is an interface claim, not a measured result.

The agent is unreliable at large rewrites

medium

The local 2.9B reasoning model failed on from-scratch generation and produced an invalid slice in a full-file repair. The driver rejected it. OpenRouter is now the default provider.

The graph adapter is not general

medium

One bias-free linear and the reference attention block are recognized. Arbitrary models must supply graph.yaml.

Evaluation is incomplete

medium

No block latency, no full mutation rerun under G2-G5, no portability run and no ablation.

The lowering was not on main

resolved

The CUDA GEMM template lived on a teammate branch. It is merged, tested on CPU and wired through G3.

What not to claim: that the full block runs, that NOMAD is portable to Trainium, that the verifier is sound, or that it beats torch.compile. None of those has been measured.
07

What remains

The critical path is GPU numbers, then PKIR v0.2, then the full block.

next
Next 48 hours

Run G4/G5 on the GPU box

Run tests/gpu/test_pipeline_gpu.py and record the differential errors and the geomean speedup.

Next week

PKIR v0.2: reductions and layouts

Add intra-tile reductions, broadcasts, exp/rsqrt and first-class layout steps. This unlocks RMSNorm and the split/merge groups.

After that

Attention state and SDPA

Running max/sum state, rescale and causal masks. This is the hardest region.

Then

NKI, mutation study, ablations, report

Portability, gate quality, kernel-only vs graph-level agent, and the ASPLOS-style report.

The single next action

Run the GPU test. A source artifact and a PTX file prove lowering. They do not prove a working kernel. The GPU run turns the vertical slice into a result.

Say

  • QKV is end to end through G3 on CPU.
  • PTX is generated for sm_86.
  • G4/G5 are wired and waiting on the GPU.
  • The full block is blocked by PKIR v0.2, not gate wiring.

Do not say

  • The full attention block works.
  • The verifier is sound for all shapes.
  • NOMAD is portable to Trainium today.
  • It is faster than PyTorch.
